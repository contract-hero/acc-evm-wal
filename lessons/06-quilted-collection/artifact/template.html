Section 1 Storage + constructor

Two storage strings (quiltId, aggregator), one immutable uint, one counter. The three constructor guards make every empty/zero deploy fail loudly instead of producing an unreachable collection.

string can't be immutable in Solidity. The convention "written once by constructor, no setter" is what makes quiltId effectively immutable — the language can't help you here.

Section 2 Self-mint with sequential ids + maxSupply cap

Two one-character decisions — post-increment + <= — define the exact [1, maxSupply] window.

The tests pin both characters: test_mint_assignsSequentialIdsAndEmits catches the increment direction, test_mint_capsAtMaxSupply catches the comparison operator.

Section 3 tokenURI — the deterministic URL

One string.concat, two SLOADs, one decimal conversion. Every token's URL derives from a SHARED prefix + a per-token id.

10 000 tokens, 2 storage strings. Off-chain consumers reproduce the URL with zero RPC calls once they know the prefix.

Section 4 setAggregator — the sunset knob

One owner-only setter. The ONLY post-deploy mutable storage slot. Deliberate minimalism.

The equivalence gate

The setAggregator_ownerCanMigrateAggregator test is the punchline: same token, different aggregator, new URL — Walrus's content-addressing makes the migration safe.
